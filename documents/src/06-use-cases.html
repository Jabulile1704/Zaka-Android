3. The two most interesting flows

3.1 UC-1 — Record an expense

FieldDetail
PreconditionThe app is installed. Nothing else — no account, no permission, no connection.
Main flow 1. Owner opens the Add tab.
2. The amount field already has focus and the decimal keypad is open.
3. Owner types an amount; both a comma and a full stop act as the decimal point.
4. Owner taps a category.
5. Owner optionally changes the date and adds a note.
6. Owner taps Save.
7. The app records the expense and returns to the list, where it appears under its day.
Alternatives 3a. The amount is empty, not a number, or zero: Save stays disabled and nothing can be submitted.
6a. Save is pressed twice: exactly one expense is recorded. (Raised as DEF-3 and now covered by test.)
PostconditionOne new record exists on the device. The month-to-date total and the day's total both reflect it.

3.2 UC-10 — Show a card at a till

FieldDetail
PreconditionAt least one card is stored, and its number can be rendered in at least one form.
Main flow 1. Owner opens the Cards tab and taps a card.
2. The app raises screen brightness to maximum.
3. The code is drawn full screen, in whichever form the card was saved as.
4. The Till scanner reads it.
5. On leaving, the app restores the previous brightness.
Alternatives 3a. The number cannot be drawn as a linear barcode: only the QR form is offered.
3b. The card was deliberately saved as Code 128: it is shown as Code 128 and never promoted to EAN-13, even if its digits happen to validate.
4a. The scanner cannot read it: the Owner reads the number printed beneath the code to the cashier.
PostconditionNothing is changed or recorded. This use case only reads.
NoteThis is the one use case that cannot be verified without a real counter. A QR code of a card number is offered because it is cheap, not because any retailer promises to accept it — which is why the linear barcode remains the default.

4. What is deliberately not a use case

Not hereWhy
Sign in, register, recover a passwordThere is no account. One person, one device.
Share with, or grant access to, another personOut of scope for 1.0; it would require a service and a privacy surface.
Back up or restoreAndroid's own backup does this. The app's part is declaring that its database should be included, which is configuration rather than a use case.
Manage categoriesThe sixteen are fixed at build time. Editing them would mean a schema that can lose records to a rename, which §2 of the ERD argues against.
Set a budget, receive an alertCandidate for 1.1. Insights answer where the money went, not whether it was allowed.
