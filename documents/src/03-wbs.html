1. How to read this

Work is decomposed to the level of a single pull request, because that is the unit this project actually ships: one issue, one branch, one review, one merge. Every work package below names its GitHub issue.

Effort is in ideal days of focused work on the package itself, excluding review and waiting. State is as at 25 November 2026, when sprints 1 and 2 were complete and awaiting merge.

4.1 Critical path

The critical path does not run through the code. It runs through Google Play: a new personal developer account must run a closed test with at least twelve testers opted in for fourteen continuous days before production access can even be applied for, and the application for access is then reviewed.

5. Assumptions and risks

RiskLikelihoodImpactResponse
Identity verification takes longer than a few daysMediumHighStart it first, before any release work. It gates everything and depends on no code.
Fewer than twelve testers can be found and heldMediumHighRecruit early and over-recruit; a tester who opts out resets their fourteen days.
Production review overrunsMediumMediumAccept. The app is complete and installable from a closed track regardless.
No physical device for the camera scannerLowMediumAn emulator cannot test a camera. Ship the typed path and mark scanning verified only when a device confirms it.
The app looks wrong once it is finally seenMediumMediumRun it on 26 November, before sprint 3 builds four more screens on the same theme.
Owner's time, not development time, becomes the constraintHighMediumAlready true. Every verification and every Play step is owner-only; sequence those first and let development fill the gaps.
If only a private release is wanted

Closed and internal testing tracks carry no twelve-tester requirement and no production review. If "published" means "installable from Play on my own phone", the project finishes in early December and phase 4 collapses to packages 4.1 through 4.3. The fourteen-day gate exists only for a public production listing.
