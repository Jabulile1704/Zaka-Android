1. Purpose and scope

Zaka records what one person spends and tells them where it went. It runs on one phone, stores everything on that phone, and talks to nothing. This document states what it must do, how well it must do it, and what it deliberately will not do.

It describes the Android port of Jabulile1704/Zaka, an iOS app already in daily use. That app is the reference: where this document says parity, the requirement is "behave as iOS does", and the iOS test suite is the specification of record.

1.1 Actors

ActorTypeInterest
OwnerHuman, primaryThe single user. Logs expenses, reads insights, carries loyalty cards. There is no second role, no sharing and no login.
Till scannerExternal systemReads a barcode off the screen at a shop counter. Cannot be tested in an emulator.
Device cameraExternal systemReads a barcode off a physical card during card entry.
Android BackupExternal systemThe only off-device copy of the data, and only if the user has backup enabled.
SpreadsheetExternal systemConsumes the CSV export. Constrains the number format far more than the display does.

1.2 Assumptions and constraints

  • One user, one device. No account, no server, no sync in 1.0.
  • Currency is South African Rand and is fixed at build time.
  • The device runs Android 8.0 (API 26) or later.
  • The store is unencrypted SQLite, readable from an unlocked phone or a device backup. This bounds what may be kept in it — see NFR-SEC-2.
  • There is no budget for a paid service of any kind, so anything requiring a backend is out of scope by construction.

3. Non-functional requirements

3.1 Usability and platform fit

IDRequirementHow it is judged

NFR-USE-2Where the device offers a wallpaper-derived palette, the app uses it; otherwise it uses its own.Android 12+ dynamic colour, with the brand scheme as fallback.
NFR-USE-3Recording an expense takes no more than four interactions from launch: tab, amount, category, save.Counted on device.
NFR-USE-4Amounts are displayed identically regardless of device locale: R1,234.56.MoneyTest.
NFR-USE-5Figures that change in place use tabular digits, so totals do not jitter.Inspection on device.

3.3 Performance

IDRequirementHow it is judged

3.4 Reliability and data safety

IDRequirementHow it is judged
NFR-REL-1No user action loses data silently. Reads never rewrite the store.ExpenseStoreTest asserts the stored key is untouched after a mapped read.
NFR-REL-2The expense database is included in device backups; nothing else is.backup_rules.xml, data_extraction_rules.xml.
NFR-REL-3A schema change ships with a migration and a schema under version control before it reaches a user.Not yet applicable at version 1 of the schema.

3.5 Security and privacy

IDRequirementHow it is judged
NFR-SEC-1The app makes no network requests, carries no analytics and no crash reporting, and requests no network permission.Manifest review; no networking dependency in the build.
NFR-SEC-2Nothing is stored that would be dangerous to read from an unlocked phone. Loyalty cards only; never payment cards.Design constraint, stated in the user manual and enforced by what the card form accepts.
NFR-SEC-3The repository contains no keys, tokens, certificates or keystores, and no real expense data..gitignore excludes backup/ and keystores from the first commit.
NFR-SEC-4The commit identity exposes no personal email address.A GitHub noreply address is used.
NFR-SEC-5The camera permission is requested only when the scanner is opened, and the app works fully without it.Sprint 3.

3.6 Maintainability and portability

IDRequirementHow it is judged

NFR-MNT-2Every dependency version is declared in one place.gradle/libs.versions.toml.
NFR-MNT-3Every change arrives through a pull request with CI passing, and carries a written reason.Branch and PR workflow; CI required on every pull request.

4. Out of scope for 1.0

ExcludedWhy
Multi-device syncNeeds a backend or a paid cloud entitlement. The iOS app has the code for it and keeps it switched off for the same reason.
Multiple users, accounts, sign-inA personal tracker. An account would add a privacy surface and a service to run, for no gain to its one user.
Budgets, limits and alertsCandidate for 1.1. Insights answer "where did it go", not "am I allowed".
Recurring expensesCandidate for 1.1.
Multiple currenciesOne user, one country. The symbol is a single constant if that changes.
Bank or SMS importWould require reading messages or a bank integration: a large privacy surface against a design principle of touching nothing.
Undo for a deletionGap, not a decision. Recorded as DEF-5 and scheduled.
On traceability

Every requirement above names the issue it came from and the test that holds it. Requirements marked Open or sprint 3 are deliberately listed with no passing test rather than quietly omitted — the point of a specification is that the gaps are visible.
